## Semantic integration boundaries

Textual conflict resolution alone does not establish correctness. The integration
preserves these boundaries across automatically merged code as well:

- Image-copy window capture uses `ScreenCapture`; PipeWire uses `Screencast`.
  A rule scoped to screencasts must not silently change meaning.
- `with_sdr_capture` covers element preparation and final rendering together;
  generic capture helpers do not independently change compositor color state.
- The shared `CaptureBuffer` replaces the obsolete internal screencopy dispatch.
  DMA-BUF consumers wait for GPU completion; SHM readback completes before ready.
- Cursor capture retains rendered geometry, window-focus restrictions and
  hotspot-only notification changes. Source/session identity is distinct from
  stream identity, and official second-frame cast classification is retained.
- Minimized windows remain discoverable by ID. A temporarily output-less mapped
  window pauses its image-copy stream rather than being treated as destroyed.
- Existing closing-animation and pending-unmap snapshot protection-generation
  handling remains in place; an upstream capture refactor is not permission to
  reuse pixels after protection tightens.

## Rollback and publication boundary

Source rollback means continuing to use the untouched original worktree and
existing accepted artifact. No destructive reset of the integration worktree is
required. The saved bundle and checkpoint preserve the exact pre-update source.

Deployment remains a separate operation. The existing daily rollback command
validates the old executable against the current configuration and selects it for
the next login; it does not restore configuration automatically. A new upstream
configuration option can therefore prevent an older executable from being selected
until configuration compatibility is deliberately restored. See [DAILY.md](DAILY.md).

Physical NVIDIA frame synchronization, HDR/VRR, monitor hotplug and suspend/resume
require hardware/session acceptance. Compilation, software rendering and a nested
Wayland window cannot establish those properties. Existing acceptance records
apply only to their recorded binaries, not automatically to this integration.

## Review-driven lock-submission corrections

Independent frame-safety review found a P1 defect in the newly integrated Spicy
path: returning `RenderResult::Submitted` while GPU fences were still pending
allowed `Niri::redraw()` to confirm a session lock before the protected frame had
actually reached KMS submission. A later queue failure could leave the old
unlocked frame visible despite that confirmation.

The correction spans `src/backend/mod.rs`, `src/backend/tty.rs` and `src/niri.rs`:

- `RenderResult::Pending` distinguishes a retained asynchronous submission from
  both success and a skipped/failed render.
- The completion callback carries the frame's lock state captured when rendering;
  it cannot reclassify an older unlocked frame using a newer session-lock request.
- Shared completion bookkeeping runs after actual queue success/failure.
  Other-output completion and removal also respect outstanding fence waits.
- Failed replacement of an unlocked output aborts the lock without confirmation.
  Failed replacement of an already-protected output retains that protection and
  still evaluates the shared completion gate.

The last rule fixes a P2 found during rereview: an unconditional early return on
failure could leave a new lock waiting indefinitely even though the previous
frame still protected every output. Final independent rereview closed both
findings; it did not claim hardware acceptance.

`src/tests/session_lock.rs` exercises production completion bookkeeping and actual
Wayland session-lock notifications with deterministic submission ordering:
pending then successful submission; pending then failure over an unlocked
output; a lock beginning while an older unlocked frame is pending; completion
and removal of another output; and failed replacement of an already-protected
frame. The tests control the bookkeeping boundary rather than requiring an
actual unsignaled NVIDIA fence or injecting DRM failures.
